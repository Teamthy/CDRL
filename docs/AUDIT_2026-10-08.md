# Platform audit — 2026-10-08

Full-platform audit of `Teamthy/CDRL` (Next.js 15 web + Express/Prisma API, pnpm
workspaces). Findings are recorded verbatim as reported, grouped by severity, with
the file/line references captured at audit time.

Line numbers refer to the tree as audited; `main` moves, so re-verify before acting
on any single reference. Remediation status for each item is tracked in the table at
the bottom of this document.

---

## P0 — user-facing breakage / data loss / blocked deploy

### 1. Learner sessions die after 2h

`apps/web/lib/learnerClient.ts:58` — `post()` (used by `learnerSignIn` /
`learnerSignUp`) omits `credentials:'include'`, while `tryRefresh` (104), `authFetch`
(121) and `signOut` (137) all send it. Cross-origin, the browser discards the
`Set-Cookie` from `apps/api/src/learnerAuth.ts:145,169`, so `/learner/refresh` always
401s and refresh-token rotation is dead code. Token is signed `'2h'`
(`learnerAuth.ts:54`) though comments say 12h.

**Fix:** add `credentials:'include'`; align the TTL and the comments.

### 2. Two tabs refreshing = logged out everywhere

`refresh.ts:66-87` `rotateRefreshToken` reads then updates non-atomically; the loser
hits the `usedAt` branch and revokes the whole family. No client single-flight
(`learnerClient.ts:116-130`).

**Fix:** atomic `updateMany({where:{tokenHash, usedAt:null}})` + count check, ~10s
reuse grace window that re-issues instead of revoking, one shared in-flight refresh
promise client-side.

### 3. Admin console shows only 50 of 141 courses

Lists ask `?limit=200` (`components/admin/ResourceManager.tsx:107`,
`app/admin/bundles/page.tsx:93`, `app/admin/pecb-exams/page.tsx:43`,
`components/admin/editors.tsx:105`) but `listQuerySchema` caps `limit` at 100
(`apps/api/src/validation.ts:93`), so `safeParse` fails and handlers silently fall
back to 50. No pagination UI.

**Fix:** raise/clamp the cap and add real pagination (`total` is already returned).

### 4. Deleting a course destroys learner data

`Enrollment` / `CourseModule` / `Recording` are `onDelete: Cascade` from `Course`
(`prisma/schema.prisma:155,172,208`) behind a plain `DELETE`
(`apps/api/src/admin.ts:276-289`).

**Fix:** unpublish/soft-delete by default; block hard delete when enrolments or
purchases exist.

### 5. Re-seeding wipes console edits

`apps/api/src/seed.ts:46` upserts with `update: course` (full-row), contradicting the
promise at the top of `pecb-catalogue.ts`.

**Fix:** `update: {}` or an explicit `--force` flag.

### 6. LMS + payments can't be enabled as shipped

`LEARNER_JWT_SECRET` and `PAYSTACK_SECRET_KEY` are in no `.env.example` and not
forwarded by `docker-compose.prod.yml` (also `PUBLIC_WEB_URL`, `NEXT_PUBLIC_GA_ID`
undocumented). Without the learner secret, signup/login/reset return 503.

**Fix:** document all of them and pass them into the `api` service.

### 7. Paid-but-not-enrolled is unrecoverable

`apps/api/src/payments.ts:128-130` returns `{already:true}` without re-granting
enrolment, and the success write + `grantEnrollment` (143-146) aren't transactional.

**Fix:** `prisma.$transaction`, and verify/re-grant in the `already` branch.

## P1 — worth doing in the same pass

### 8. `GET /api/v1/courses` ships unused long-form bodies

`apps/api/src/index.ts:129` has no `select`, so every course's long-form `details`
ships: measured 265 KB for 116 rows, 86% unused — and the array is passed into
CLIENT components (`CourseMarketplace`, `PecbPortfolioShowcase`, `CourseCard`), so it
lands in the RSC payload of `/`, `/training`, `/partnerships`.

**Fix:** `select` card fields on list endpoints; pass a trimmed view model to clients.

### 9. One rate-limit bucket for unrelated endpoints; 429s reported as success

One 6/min/IP bucket covers contact + applications + every learning-plan mutation
(`index.ts:52-64`). And `AddToPlanButton.tsx:22-24` ignores `addLearningPlanItem`'s
`{ok:false}` — it says "Added to plan" and redirects on a 429 where nothing was saved.

### 10. Redis failure = 500 on every mutation

`index.ts:56-60` is fail-closed. Fall back to `RateLimiterMemory` instead.

### 11. Payments endpoints unthrottled; pending rows accumulate

`/payments/initialize` and `/payments/verify/:reference` have no rate limit
(`payments.ts:77-119, 123-152`); `initialize` writes a purchase row before Paystack
answers, so pending rows accumulate forever.

### 12. Auth limiter can lock a user out of recovery

Auth limiter is 5/min/IP shared across login+signup+forgot+reset
(`learnerAuth.ts:48`) and in-memory only — a user can be locked out of the recovery
flow itself.

### 13. Unbounded growth / missing indexes

`RefreshToken` rows never purged (no index on `expiresAt`), `LearningPlan` rows for
anonymous sessions never expire, pending `Purchase`s never expire, `ContactEnquiry`
lacks the `status`/`createdAt` index its admin list needs.

### 14. Fake totals and silent truncation on LMS admin lists

`/admin/lms/users` + `/lms/enrollments` (`take 200`), `/lms/modules` +
`/lms/recordings` (`take 500`) return `total = items.length`
(`admin.ts:409-421, 493-505, 584-596, 647-659`). `/admin/audit-log` ignores `offset`.

### 15. Learning-plan badge flicker

`Header.tsx:19-31` re-fetches the learning plan on every route change; bag badge
flickers to 0.

## Quick UX bugs (small diffs, all confirmed)

16. `components/layout/SearchPanel.tsx` — the header search input is inert: no state,
    no handlers, no results.
17. `app/events/page.tsx:79` links to `/contact?interest=<slug>` but `ContactForm`
    never reads search params (and the slug isn't a dropdown option) — context dropped.
18. `ContactForm.tsx:41-47` discards `submitContact`'s message; always shows the
    generic error, so 429 users get no guidance.
19. `app/learner/[slug]/CoursePlayer.tsx:29-39` — `tick()` has `try/finally`, no
    `catch`: failed "mark complete" is a silent unhandled rejection.
20. `app/learner/onboarding/OnboardingFlow.tsx:52-65` — `finish()` never checks
    `res.ok`; a 401/500 still redirects to `/learner`, which loops back to onboarding.
21. `app/events/page.tsx:54` — `(others.length ? others : events)` renders exam-only
    events twice.
22. `app/events/page.tsx:19-26` — `toLocaleDateString` with no `timeZone` on an ISR
    page: event dates can render a day off.

### Deliberately not changed in this pass

These were flagged during the audit and left alone on purpose; each is a
judgement call rather than an oversight, and they are recorded so the next
pass starts from the same place.

Before enforcing it, review the reports in a real browser, and fix the employer-letter print helper (row 33), which would likely be blocked. | Access token in `localStorage` | **Decided, not built:** move the tokens to httpOnly cookies. Still needed: the API on that subdomain (DNS and Render), CORS credentials for the web origin (already set in `index.ts`), Origin checks on cookie-authenticated writes, and a browser check of learner and admin sign-in. Merging before the API moves would break sign-in for everyone. |
